# 修复 `npm run dev` 本地无法拉起

## 根因
1. **OOM 主因**：`src/lib/prisma.ts:1` 从深层路径 `../../node_modules/.prisma/client-new` 导入 PrismaClient，导致 `serverExternalPackages: ["@prisma/client"]` 匹配不到，Prisma client 仍被 Turbopack 内联 → Windows 上编译 `/reading` 时 V8 堆溢出崩溃（`HashMap::Initialize`，devlog.txt 实锤）。
2. **崩溃后遗症**：崩溃残留的 node 进程占住 3000 端口 → 之后启动立即 `EADDRINUSE`（.next-dev.log 实锤）。
3. `.next` 缓存停留在 8月2日崩溃当天，可能损坏。

## 修复步骤

### 第 0 步：复现定位
后台运行 `npm run dev` 抓取真实报错输出，确认是 EADDRINUSE 还是 OOM 崩溃（或其它），按分支执行后续步骤。

### 第 1 步：清理端口占用（若为 EADDRINUSE）
`netstat -ano | findstr :3000` 找到 PID → `taskkill /PID <pid> /F` 结束残留进程。

### 第 2 步：修 OOM 根因（核心）
- **prisma/schema.prisma**：generator 去掉自定义 `output = "../node_modules/.prisma/client-new"`，回归默认输出目录。
- **src/lib/prisma.ts**：改回标准导入 `import { PrismaClient } from "@prisma/client"`，使 `serverExternalPackages` 真正生效。
- **prisma/seed/index.ts**：同步改为 `@prisma/client` 导入。
- **package.json**：dev 脚本加内存兜底：`"dev": "cross-env NODE_OPTIONS=--max-old-space-size=4096 next dev"`。
- 运行 `npx prisma generate` 重新生成客户端（同时更新注释中过时的"Database: SQLite"描述）。

### 第 3 步：修正 next.config.mjs
- `output: "standalone"` 改为环境变量门控：`output: process.env.NEXT_OUTPUT_STANDALONE === "1" ? "standalone" : undefined`，并在 **Dockerfile** builder 阶段加 `ENV NEXT_OUTPUT_STANDALONE=1` → 本地 `npm start` 恢复可用，Docker 构建不受影响。
- `outputFileTracingIncludes` 从 `experimental` 移到顶层（Next 16 规范位置），路径 `client-new` 改为 `client`。

### 第 4 步：清理缓存并验证
- 删除旧的 `.next` 目录。
- `npm run dev` 启动 → curl 验证 `/`、`/reading`、`/word-library` 均返回 200（重点触发此前 OOM 的 /reading 编译）。
- `npm run build && npm start` 验证生产模式可用。

### 可选清理（Postgres 迁移已完成，征得同意后做）
移除 `better-sqlite3` devDep、`prisma/dev.db`、`scripts/migrate-devdb-to-pg.js`、遗留的 `node_modules/.prisma/client-new` 目录。

## 涉及文件
`prisma/schema.prisma`、`src/lib/prisma.ts`、`prisma/seed/index.ts`、`package.json`、`next.config.mjs`、`Dockerfile`
